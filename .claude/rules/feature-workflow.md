# 新功能流程（每个功能都必须走，不可跳步）

触发：Logan 说"做 / 实现 / 开始"某个功能，或者输入 `/feature`。
本文件在本地 Claude Code 和 Projects 云端线程里都会自动加载，规则相同。

## 1. 确认范围
读 `docs/roadmap.md`。这个功能属于"当前位置"里的里程碑吗？前置项完成了吗？
不属于或没完成 → 停下来说明，等 Logan 决定。

## 2. 建分支
从最新的 main 拉出 `feat/<milestone>-<short-name>`。一个功能一个分支、一个 PR。

## 3. 出方案（这一步不改任何代码文件）
先读相关代码和文档（`docs/architecture.md`、`docs/security-checklist.md`、M1 样板模块）。方案包括：
1. 目标和验收标准（用户视角）
2. 要新增或修改的文件
3. 数据表 / 迁移变更
4. 接口：路径、请求、响应、错误码
5. 前端：页面和状态（加载、空、错误、移动端）
6. 测试清单：正常路径、错误路径、权限
7. 安全清单：逐条写"涉及 / 不涉及 / 怎么处理"
8. 关键设计的理由，以及考虑过的替代方案
9. 是否需要新依赖 → 需要的话先按 `adr-workflow.md` 写 ADR，被采纳前不能安装

## 4. 停下，等 Logan 确认
没有明确的"可以 / 确认 / go"之前不写代码。Logan 要求修改就改方案，再次确认。

## 5. 先写测试
按方案写测试，运行并确认它们失败。

## 6. 实现
写到测试全部通过。遵守分层规则和 `docs/architecture.md` 第 7 节的约定。

## 7. 跑全部检查
lint、类型检查、全量测试。全部通过才继续。把结果的汇总行贴出来。

## 8. 审查
按 `review.md` 做安全审查和代码审查（能用子代理就用子代理，让审查在独立上下文里进行）。修完所有"必须修"的问题后，重新跑第 7 步。

## 9. 更新文档
- `docs/roadmap.md`：勾选完成项
- 架构或约定有变化 → 更新 `docs/architecture.md`
- 新的常用命令 → 补到 `CLAUDE.md`

## 10. 提交并开 draft PR
Conventional Commits，按逻辑拆成小的 commit，文档和代码一起提交。开 **draft** PR，描述按 `.github/pull_request_template.md` 写（英文）。

## 11. 交给 Logan
输出：改了什么（3–5 条）、怎么手动验证（包括手机上）、PR 链接。然后停下。
**合并只由 Logan 决定。**

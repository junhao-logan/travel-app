# ADR 流程

触发：要引入新技术、新依赖、新服务，或者 Logan 要确定一条"待定"的决策（也可以用 `/adr`）。

1. 看 `docs/decisions/README.md` 的索引：这个主题已经有 ADR 了吗？
   - 有且状态为"待定" → 在这个文件上继续
   - 没有 → 新建 `docs/decisions/NNNN-short-title.md`（编号顺延），并加入索引
2. 涉及价格、免费额度、版本、服务条款等会变化的信息 → 先上网核实，注明核实日期和来源链接。
3. 按模板写清楚：背景、至少两个选项（各自优缺点）、你的建议和理由。
4. **明确标注"这是 Claude 的建议"**，状态保持"待定"。
5. 按 `CLAUDE.md` 第 6 条的讲解格式向 Logan 解释取舍，包括面试被问到时怎么回答。
6. Logan 明确拍板后：填写"决定 / 理由 / 代价"，状态改为"已采纳"，更新索引；影响到 `docs/architecture.md` 里【建议】项的，改为【已定】。
7. 已采纳的 ADR 不改内容。改主意就写新 ADR，把旧的标记为"已废弃，被 NNNN 取代"。
8. 一次只讨论一条 ADR。

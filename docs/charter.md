# 项目章程（Charter）

> 定义"做什么、不做什么、按什么原则做"。范围有变化时先改这里，再动代码。

## 1. 一句话描述
一个旅游照片分享平台：用户上传旅行照片、整理成相册，其他人可以浏览。之后逐步升级为图文帖子和旅游攻略（类似小红书），再到带关注和 Feed 的个人主页（类似 Instagram）。

## 2. 目标
1. **真实产品**：做一个真正有人用的网站，不是 demo。体验、稳定性、数据安全都按正式产品的标准来。
2. **工程质量优先**：基建稳固、代码工整、风格一致。慢没关系，返工才是最大的成本。
3. **可持续运营**：上线后能长期运行，包括备份、监控、成本可控、能处理违规内容和用户的数据请求。
4. **附带价值**：可以写进简历。但做决定以"对产品好"为准，不以"简历好看"为准。

## 3. 开发方式
- 主要由 Claude Code 编写代码。Logan 负责：审方案、读 diff、做决定。
- Logan 要能解释每个设计选择，所以方案必须写清楚理由和取舍。
- 产品决定（做什么功能、界面怎么设计）和技术决定一样，都需要 Logan 确认。
- 完整流程见 `docs/workflow.md`。

## 4. 产品质量标准（每个功能都要满足）
- **移动端优先**：大多数用户用手机浏览和上传，所有页面都要响应式适配，在手机上好用。
- **体验完整**：加载状态、空状态、错误提示、上传进度都要有，不能出现白屏或无反馈。
- **速度**：图片懒加载，按尺寸返回对应缩略图；首页在手机 4G 网络下也要快。
- **数据可控**：用户可以删除自己的照片和账号，删除后对象存储里的文件也要清掉。

## 5. 阶段
| 阶段 | 主题 | 核心内容 |
|---|---|---|
| v1 | 照片分享 | 账户、照片上传、相册、公开浏览、部署、公开发布准备 |
| v2 | 帖子与攻略 | 多图帖子、标签、点赞、评论、旅游攻略、按地点搜索 |
| v3 | 社交 | 关注、Feed 流、个人主页、通知 |

**规则：上一阶段全部验收通过前，不开始下一阶段。**

## 6. 不做的事（Non-goals）
- v1 不做：评论、点赞、关注、推荐算法、视频、私信、原生移动 App（移动端用响应式网页，以后可以考虑 PWA）。
- 不追求功能多，追求每个功能都扎实、有测试、真正好用。
- 没有 ADR 不引入新技术或新依赖。

## 7. 原则
1. 基建先于功能：M0 全部完成前不写业务功能。
2. 一次只做一件事：一个功能一个分支、一个 PR。
3. 先方案后代码：方案经 Logan 确认后才能实现。
4. 测试是一致性的保障：没有测试的功能视为未完成。
5. 决定要留痕：重要选择写 ADR。
6. 安全是默认项：每个功能都要过安全清单。
7. 不加没要求的东西：有想法就提出来，由 Logan 决定。

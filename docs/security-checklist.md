# 安全清单

> 每个功能的方案都要逐条说明"涉及 / 不涉及 / 怎么处理"。security-reviewer 子代理会对照这份清单审查代码。

## 认证与会话
- [ ] 密码用 argon2 哈希，不记录明文、不写进日志
- [ ] 会话方案按 ADR-0004；cookie 设置 httpOnly、Secure、SameSite
- [ ] 会改数据的请求有 CSRF 防护（SameSite + CSRF token），并有测试
- [ ] 登录、注册、找回密码接口限流；错误提示不能暴露账号是否存在

## 授权
- [ ] 每个读写操作都在 service 层检查资源归属（防 IDOR）
- [ ] 私有资源在**所有**接口都访问不到（列表、详情、搜索、分享链接），并且有测试覆盖
- [ ] 管理员接口单独鉴权

## 输入与输出
- [ ] 所有输入都经过 Pydantic 校验；字符串有长度上限；分页有上限
- [ ] 不拼接 SQL（只用 ORM 或参数化查询）
- [ ] 用户输入在前端渲染时转义（防 XSS）；不使用 `dangerouslySetInnerHTML`
- [ ] 错误响应不暴露堆栈、SQL 或内部路径

## 上传
- [ ] 类型白名单 + 大小上限 + magic bytes 校验
- [ ] 清除 EXIF；原图尺寸有上限
- [ ] presigned URL 时效短，并限定 content-type 和大小
- [ ] 用户存储配额和上传频率限制

## 密钥与配置
- [ ] 密钥只放在环境变量；`.env` 不进 git
- [ ] CORS 只允许自己的前端域名
- [ ] 生产环境关闭 debug 和 API 文档的公开访问（或加鉴权）

## 依赖与数据
- [ ] 依赖版本锁定；CI 做漏洞扫描
- [ ] 删除操作连带清理对象存储中的文件
- [ ] 日志里没有个人信息（邮箱、IP 按需脱敏）

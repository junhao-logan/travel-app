# 决策记录（ADR）

每条重要决策一个文件：`NNNN-short-title.md`。状态：待定 / 已采纳 / 已废弃。
已采纳的 ADR 不修改内容；改主意时写一条新 ADR，把旧的标记为"已废弃，被 NNNN 取代"。

## 选型原则（Logan 于 2026-11-22 确定）
1. 默认选行业内使用最广的方案（文档多、人人熟悉、以后的开发者和 Claude 都能接手）。
2. 如果最主流的方案要收费，先用免费或低价的方案，但必须保证以后能方便地换成主流方案：
   通过标准协议或我们自己的一层薄封装来调用，不在业务代码里直接依赖某家服务商的专有 API。
3. 每条 ADR 写明"以后什么情况下重新评估"，以及要换的话需要改哪些地方。

## 模板
```markdown
# ADR-NNNN：标题
- 状态：待定 / 已采纳 / 已废弃
- 日期：YYYY-MM-DD
- 背景：要解决什么问题
- 选项：
  - A：优点 / 缺点
  - B：优点 / 缺点
- 决定：
- 理由：
- 代价：接受了哪些缺点
```
